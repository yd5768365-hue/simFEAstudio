# SimFEA Studio 开发日志 - 2026-05-11

## 今日目标

开始按照 `sim-main` 的可借鉴架构思路优化 SimFEA Studio。今天不追求功能扩张，而是先把已经跑通的远程运行闭环整理成更适合长期维护的工程结构。

本轮优化重点：

- 保持现有 API 和前端行为不变。
- 不重写远程运行逻辑。
- 不触碰 `.simfea/config.json` 中的私人服务器配置。
- 先把 `src/backends/main.py` 中最基础、最容易独立的职责拆出去。

## 背景判断

当前项目已经具备下面的 POC 闭环：

```text
Tauri/Vue 前端
  -> FastAPI sidecar
  -> SSH/Slurm 远程运行
  -> 实时日志
  -> .simfea/runs 本地归档
  -> 结果摘要/VTK/学习报告
```

这个闭环已经证明项目方向成立，但 `src/backends/main.py` 承担了太多职责：

- API 应用入口。
- 配置文件读取。
- SSH 节点配置。
- 运行任务 dataclass。
- `.simfea/runs` 归档读写。
- 日志事件写入。
- 学习报告和学习导出。
- 远程 SSH/Slurm 执行。
- 结果摘要和 VTK 生成。

如果继续在这个文件里接 CalculiX、OpenFOAM、Elmer，后期会很难维护。所以今天先做第一步“瘦身”。

这次拆分遵守三个约束：

- 不修改前端接口。
- 不修改 `.simfea/config.json`。

## 第四轮优化：Slurm runner 小步拆分

### 目标

继续沿着 runner 抽象推进，但只移动低风险函数。`execute_slurm_run` 暂时不移动，因为它同时处理任务状态、SSE、日志同步、结果归档、学习报告生成和取消语义。

本轮只拆：

```text
Slurm 脚本生成
sbatch 提交脚本生成
JobID 解析
squeue 状态查询
scancel 请求
```

### 新增文件

新增：

```text
src/backends/simfea_api/runners/slurm.py
```

当前包含：

```text
build_slurm_job_script
build_slurm_submit_script
parse_sbatch_job_id
query_slurm_state
request_slurm_cancel
```

其中 `request_slurm_cancel` 只负责发 `scancel`，不负责写 SSE 事件。`main.py` 里保留 `cancel_slurm_job` 包装函数，因为它还要向前端发“正在取消”的实时状态。

### main.py 变化

`main.py` 删除了以下旧定义：

```text
build_slurm_job_script
build_slurm_submit_script
parse_sbatch_job_id
query_slurm_state
```

并从 runner 模块导入同名能力。

保留在 `main.py` 中的 Slurm 编排函数：

```text
execute_slurm_run
download_slurm_artifacts
sync_remote_log_file
read_remote_text
download_remote_file
cancel_slurm_job
```

保留原因：

- 它们还依赖 `emit_remote_event`。
- 它们需要写本地日志和 artifacts。
- 它们和当前 SSE 实时日志通道耦合较深。
- 贸然移动会让调试面变大。

## 第七轮优化：执行器收尾统一化

```text

emit_finished_event
```

- `persist_run_outputs(run)`: 统一执行

异常结束分支

- finished 事件结构更一致。
