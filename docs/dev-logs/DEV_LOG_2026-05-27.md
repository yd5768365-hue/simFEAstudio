## 一、为什么要放进 SimFEA Studio

最近的一维杆探索已经形成了一个很小但完整的验证闭环：

```text
问题定义
解析解
PINN
CalculiX
ANSYS MAPDL
结果对比
失败记录
学习反思
```

其中一维杆拉伸问题已经完成了四路对比：

```text
解析解：u(L) = 0.0476190476 mm
PINN：u(L) = 0.0476188250 mm
CalculiX：u(L) = 0.04761905 mm
ANSYS：u(L) = 0.047619048 mm
```

这说明它不只是文章内容，也可以沉淀成可复用的验证算例。

如果单独做一个 `pinn-fem-benchmark` 仓库，短期看起来清晰，但长期会让路线分散。更合理的做法是把它作为 SimFEA Studio 的一个模块：

```text
Benchmark Lab / 验证算例库 / PINN-FEM 对比实验
```

这样它能服务 SimFEA Studio 的主定位：不造求解器，而是管理求解器、运行证据和学习记录。

---

## 二、模块定位

建议名称暂定为：

```text
Benchmark Lab
```

或中文：

```text
验证算例库
```

模块职责：

```text
管理标准力学问题
运行解析解 / PINN / CalculiX / ANSYS
生成统一结果表
记录误差、失败原因和学习笔记
```

非目标：

```text
不做新的有限元求解器
不把 SimFEA Studio 改成 PINN 专用平台
不一开始做复杂自动化平台
不立即引入复杂二维/三维工业案例
```

PINN 在这里是一个被验证的方法，不是整个项目的中心。

## 三、第一阶段最小闭环

第一阶段只做两个 case：

```text
rod_tension
rod_distributed_load
```

### Case 1: rod_tension

一维杆端部拉伸：

```text
u''(x) = 0
u(0) = 0
EAu'(L) = P
```

目标：验证最小四路闭环。

### Case 2: rod_distributed_load

一维杆分布载荷：

```text
EAu''(x) + q = 0
u(0) = 0
EAu'(L) = 0
```

目标：验证 PINN 是否能学习二次位移曲线，并和 FEM/解析解对比。

## 九、长期方向

Benchmark Lab 如果持续推进，可以逐步形成 SimFEA Studio 的核心学习价值：

```text
每个算例都能回答：
这次验证什么？
解析解是什么？
PINN 是否对上？
CalculiX 是否对上？
ANSYS 是否对上？
误差在哪里？
失败原因是什么？
还有什么没搞明白？
```

这和 SimFEA Studio 的长期定位一致：

```text
不只是运行仿真，
而是把每一次仿真变成可追溯、可比较、可沉淀的学习证据。
```
