# Dev Log 2026-06-15 — 后端架构重构：路由拆分、执行模块提取、API 客户端收口

## 核心决策

### 主模块瘦身：`main.py` 从 350+ 行 → ~150 行

之前 `main.py` 是万能文件：FastAPI app 工厂 + 路由定义 + 执行逻辑 + 工具函数，全部混在一起。随着功能增加，文件膨胀到 350+ 行，任何改动都需要在巨大的文件中翻找。

今天完成三步拆分，让 `main.py` 只做一件事：**App 工厂和生命周期管理**。

---

## 完成内容

### 1. 提取 runs 路由 → `src/backends/routers/runs.py`

**原状：** `main.py` 包含 15 个 `/v1/runs/*` 端点（list、get、demo、slurm-demo、solver-run、workflow、note、report、cancel、events 等），占 700+ 行。

**拆分后：**
- `src/backends/routers/runs.py` — 808 行，独立路由器，包含所有 runs 端点
- `src/backends/state.py` — 18 行，共享可变状态（`remote_runs` 内存注册表），供 main.py 和 routers/runs.py 共用
- `main.py` — 仅保留 `app.include_router(runs_router)`

**关键设计：**
- `remote_runs: dict[str, RemoteRun]` 放在独立 `state.py`，避免 main.py 和 runs router 循环导入
- runs router 通过 `try/except ImportError` 懒导入 execution 函数（demo、cancel、workflow 启动等），保持 router 不直接依赖执行层

### 2. 提取执行模块 → `src/backends/execution/__init__.py`

**原状：** `main.py` 包含 `execute_local_run`、`execute_remote_run`、`execute_slurm_run`、`execute_local_workflow_run`、`_run_local_command`、FRD 指标提取、STA 进度轮询等 900+ 行执行逻辑。

**拆分后：**
- `src/backends/execution/__init__.py` — 1054 行，纯执行层，无 FastAPI 依赖
- `main.py` — 通过 `from .execution import (...)` 导入需要的函数

**关键设计：**
- execution 模块**不导入** `fastapi`、`sse_starlette`、`EventSourceResponse`，符合 `check_backend_boundaries.py` 边界规则
- 事件发射函数 `emit_remote_event`、`emit_finished_event` 保留在 execution 模块，因为它们是执行过程的一部分

### 3. 前端 experiment API 收口 + `path`-style 参数编码修复

**原状：** `ExperimentLab.vue`、`ResearchView.vue`、`SolverDevView.vue`、`useExperimentFiles.ts` 各自直接 `fetch()` experiment 端点，没有统一封装。

**问题发现：**
- typed client 的 `encodeURIComponent` 会把文件路径中的 `/` 编码为 `%2F`
- 导致 `/v1/experiment/files/learning/benchmarks/rod_tension/problem.md` 变成 `...%2Frod_tension%2Fproblem.md`
- FastAPI 的 `{file_path:path}` 参数无法正确匹配，返回 404

**修复方案：**
- `app/api/client.ts`：新增 `pathParams` 字段，标记哪些参数需要 `encodeURI`（保留 `/`）而非 `encodeURIComponent`
- `app/api/simfeaClient.ts`：experiment `filePath` 标记为 `pathParams: ['filePath']`
- `listExperimentFiles`：响应归一化，把 `benchmarks/...` 路径前缀统一补成 `learning/benchmarks/...`

**新增回归测试：**
- `app/api/client.test.ts` — 60 行，验证 `encodeURIComponent` vs `encodeURI` 分支
- `app/api/simfeaClient.test.ts` — 57 行，验证 experiment 端点 URL 生成

### 4. 死代码清理

- `main.py`：358 行 → 154 行，零逻辑变化

## 架构现状

```text
src/backends/
├── main.py              # App 工厂 + 生命周期（~150 行）
├── state.py             # 共享内存状态（remote_runs）
├── cli.py               # pip 入口
├── execution/           # 执行层（local/remote/slurm/workflow/docker）
│   └── __init__.py      # 1054 行，纯执行逻辑
├── routers/             # 路由层
│   ├── _helpers.py      # 共享辅助函数
│   ├── benchmarks.py
│   ├── compute_nodes.py
│   ├── config.py
│   ├── experiments.py
│   ├── knowledge.py
│   ├── preflight.py
│   ├── runs.py          # 808 行，运行相关端点
│   └── toolchain.py
└── simfea_api/          # 服务层
    ├── config.py
    ├── run_archive.py
    ├── runners/         # ssh/slurm/solver/workflow/remote_files
    ├── learning.py
    ├── results.py
    └── ...
```

边界规则：
- `simfea_api/` 不导入 `main`（无循环导入）
- `runners/` 不导入 `fastapi` 或 `sse_starlette`（纯执行）
- `execution/` 不导入 `fastapi`（纯执行）
