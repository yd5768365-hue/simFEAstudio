# 致2030：AI+有限元探索笔记

你好，未来的我。

当你看到这篇文字的时候，或许已经是三五年后了。我不知道那时的 CAE 行业变成了什么样：是 PINNs 已经成为商用软件里的标准求解器？还是大型 AI 模型已经可以根据自然语言直接输出高精度的应力应变云图？

回顾现在的我，作为一名有限元开发工程师，正站在一个技术范式转移的十字路口。一方面，是历经几十年发展、坚如磐石却也日益显现性能瓶颈的传统有限元理论；另一方面，是狂飙突进、充满无限可能却又经常像个黑盒的深度学习。

传统的路，前辈们已经走到了极致；未来的路，AI+科学计算，或者说 AI4Science，才刚刚拉开序幕。

开设这个专栏，是我送给未来自己的一份礼物。它不是高高在上的教科书，而是一份探索者日志。在这里，我会记录下：

- 我读过的 Paper 与敲下的代码：从传统 PDE 到基于 PyTorch 的 PINNs 实现。
- 我踩过的坑与流下的泪：那些 loss 死活降不下来、预测结果完全不符合物理常识的崩溃瞬间。
- 传统工程与前沿 AI 的碰撞：我们该如何让神经网络不仅学会拟合数据，更懂得敬畏物理定律？

也许这里面的很多想法在未来看来会显得非常稚嫩，甚至大方向都被证明是错的。但这又有什么关系呢？科学的探索本来就是不断试错的过程。

如果屏幕前的你，刚好也走在这条充满迷雾却又繁星点点的交叉领域之路上，欢迎你关注这个专栏。让我们一起在这个计算力学的奇点时代，留下一点属于我们自己的脚印。

未来的我，希望你还在坚持，希望你已经看到了我想象中的风景。

## 收录项目：SimFEA Studio

这个专栏的第一个长期实践项目，叫 **SimFEA Studio**。

它不是一个新的有限元求解器，也不是想一口气替代 Abaqus、Ansys、CalculiX、OpenFOAM 或 Elmer。它更像是一个面向个人研究和学习沉淀的仿真工作台：把一次仿真从“跑完就散落在终端和文件夹里”，变成一份可以回放、可以解释、可以积累的工程证据。

当前它的核心闭环是：

```text
远程运行 -> 实时日志 -> 结果归档 -> 可视化 -> 学习笔记/报告
```

也就是说，每一次计算不仅留下一个结果文件，还会留下输入、命令、stdout/stderr、退出码、远程工作目录、结果摘要、VTK 可视化文件和个人复盘笔记。对我来说，这件事很重要：有限元开发和 AI4Science 探索并不是只看最后一张云图，真正有价值的是中间那些判断、失败、修正和证据链。

在架构上，SimFEA Studio 目前采用 Tauri + Vue + FastAPI 的桌面侧车模式。前端负责交互、运行记录和结果展示；Python sidecar 负责计算节点连接、任务启动、SSE 实时日志、结果归档和学习报告生成。计算可以通过 SSH 或 Slurm 跑到远程节点上，结果再被收回本地 `.simfea/runs` 证据仓库。

最近项目开始接入真实求解器。这里我借鉴了 OpenCAEHub 的一个关键思想：**求解器不应该硬编码在主程序里，而应该通过声明式配置接入**。OpenCAEHub 用插件配置和适配器把外部求解器组织起来；SimFEA Studio 则先用更轻量的 JSON 配置描述求解器：

- 求解器别名和类型，例如 `calculix`、`openfoam`、`elmer`。
- 可执行程序，例如 `ccx`、`icoFoam`、`ElmerSolver`。
- 输入文件模板。
- 运行命令模板。
- 需要归档的输出文件通配符。

这样做的目的不是追求架构漂亮，而是为了以后接入更多求解器时，不必每接一个工具就改一堆主流程代码。SimFEA Studio 只负责统一的运行证据链，具体求解器则通过 adapter 描述自己的输入、命令和产物。

当前第一批被纳入适配层的求解器包括：

- **CalculiX**：作为结构有限元方向的第一条真实求解器路径。
- **OpenFOAM**：作为流体方向的入口，后续需要接入真实 case 模板。
- **Elmer**：作为多物理场方向的延伸。

这还远远不是完整 CAE 平台。它现在更像一座桥：一端连接传统有限元工作流，另一端连接未来可能出现的 AI 辅助建模、AI 结果解释、PINNs 替代/加速、自动生成仿真报告等能力。

我希望它最终能回答一个很朴素的问题：

> 当 AI 开始进入有限元开发时，我们能不能先把每一次工程计算变成可追踪、可复盘、可学习的数据资产？

如果答案是可以，那么 SimFEA Studio 就不只是一个工具。它会成为我在 AI+有限元这条路上留下脚印的地方。

## 近期探索方向

接下来，这个项目会沿着几条线继续推进：

- 用真实 CalculiX 算例跑通结构有限元闭环。
- 为 OpenFOAM 和 Elmer 补充更完整的 case 模板和结果解析。
- 把每次运行的输入、结果、日志和学习笔记组织成更稳定的数据格式。
- 逐步引入 AI：先做运行报告解释、错误诊断和文献辅助，再探索 PINNs 或神经算子与传统求解器的结合。

写到这里，我其实知道这条路不会轻松。有限元不是只会调用库，AI 也不是一句 prompt 就能解决物理问题。它们相遇的地方，既有机会，也有大量脏活、细活和失败。

但这正是值得记录的原因。

致未来的我：如果 2030 年的你已经走到了更远的地方，请别忘了今天这个起点。这里有一个还很粗糙的工具，一个还不成熟的想法，还有一个愿意继续试错的人。
