# SimFEA Studio 开发日志 - 2026-05-07

## 0. 本日志用途

这份日志是给未来的自己或其他 AI agent 看的交接文件。目标不是简单记录“改了什么”，而是把今天每一步的判断、命令、故障、修复、当前状态和下一步开发方向写清楚。

今天项目从一个 `vue-tauri-fastapi-sidecar` 模板，推进到了 SimFEA Studio 的第一个真实核心原型：

> 本地桌面界面通过 FastAPI 侧车服务，代替用户在远程 SSH 终端执行命令，并把远程输出实时接回本地界面。

这条链路是后续远程求解器、远程算力调度、运行记录、物证仓库的基础。

## 1. 初始目标与项目定位

### 1.1 用户对项目的定位

用户明确表达：SimFEA Studio 不是新的仿真引擎，不是商业 CAE 竞品，也不是 AI 自动化工具。

项目定位逐步收敛为：

- 机械/仿真领域的个人版 Cherry Studio。
- 不造求解器，只管理求解器、算力、运行环境和学习记录。
- 本地桌面端负责“看”和“发命令”。
- 远程服务器、WSL、Docker、未来的调度器负责真正计算。
- 每一次运行都要变成学习物证：输入、命令、日志、结果、退出码、复盘。

今天最重要的架构共识：

> SSH、WSL、Docker、本地 shell 在 SimFEA Studio 眼里都是“命令执行通道”。区别只是命令被送到哪里执行。

### 1.2 关键抽象

后续系统应围绕 Runner / 运行器继续演化：

- `LocalRunner`：本机命令。
- `WslRunner`：WSL 发行版命令。
- `DockerRunner`：容器命令。
- `SshRunner`：远程 SSH 命令。
- 未来可能加入 `SlurmRunner` / `SchedulerRunner`。

统一事件模型应类似：

```json
{
  "run_id": "run_xxx",
  "type": "stdout",
  "line": "remote_step=1"
}
```

这会让前端不关心任务是在本地、WSL、Docker 还是远程服务器运行。

## 9. 远程节点初始探测接口

### 9.1 新增接口

在 `src/backends/main.py` 中新增：

```text
GET /v1/compute-nodes/shh1/probe
```

功能：

- 后端调用 SSH。
- 远程执行探测命令。
- 返回主机、用户、CPU 核心数、当前目录。

### 9.2 初始实现问题

最初后端直接执行：

```python
["ssh", "shh1", remote_command]
```

在解释器临时服务中能成功，但在 PyInstaller/Tauri sidecar 中失败或超时。

### 9.3 遇到的问题 1：sidecar 内调用 `ssh shh1` 超时

接口返回：

```json
{
  "exit_code": -1,
  "stderr": "Command timed out after 20s."
}
```

直接在 PowerShell 中执行 `ssh shh1` 秒通。

判断：

- 打包后的 sidecar 进程可能读不到用户 `.ssh/config`。
- 或者 SSH 子进程继承了 Tauri sidecar 的 stdin，卡在输入/认证流程。

### 9.4 修复 1：不依赖别名，使用绝对 SSH 参数

新增常量：

```python
SHH1_HOST = "cloud.dghpc.com"
SHH1_PORT = "1014"
SHH1_USER = "dg001767"
SHH1_KEY_PATH = os.path.expanduser(r"~\.ssh\shh1_rsa")
```

后端改为构造完整 SSH 命令：

```python
ssh -o BatchMode=yes -o ConnectTimeout=8 -o StrictHostKeyChecking=accept-new -i C:\Users\19730\.ssh\shh1_rsa -p 1014 dg001767@cloud.dghpc.com <command>
```

### 9.5 遇到的问题 2：仍然超时或连接关闭

打包后仍出现：

```text
Command timed out after 20s.
```

后来加了非交互参数后变成：

```text
Connection closed by 198.18.0.45 port 1014
```

### 9.6 修复 2：固定系统 OpenSSH 路径

新增：

```python
SSH_EXE = r"C:\Windows\System32\OpenSSH\ssh.exe"
```

并在 SSH 命令中使用绝对路径，避免 sidecar 内 PATH 解析到不同 ssh 程序。

### 9.7 修复 3：完全非交互执行

在 SSH 参数中增加：

```text
-n
```

并在 `asyncio.create_subprocess_exec` 中设置：

```python
stdin=asyncio.subprocess.DEVNULL
```

这是关键修复。它避免 SSH 子进程从 Tauri sidecar 的 stdin 读取内容，保证远程命令是非交互执行。

### 9.8 当前 probe 接口成功

## 10. 远程实时任务 MVP

### 10.1 目标

实现用户描述的理想状态：

> SimFEA Studio 代替用户在远程终端输入命令，远程服务器执行，输出实时回到本地界面。

本阶段不跑求解器，只跑一个远程 demo 命令，证明实时通道。

### 10.2 后端新增运行状态对象

在 `src/backends/main.py` 中新增：

```python
@dataclass
class RemoteRun:
    run_id: str
    status: str = "created"
    queue: asyncio.Queue = field(default_factory=asyncio.Queue)
    process: Optional[asyncio.subprocess.Process] = None
    exit_code: Optional[int] = None
```

全局任务表：

```python
remote_runs = {}
```

### 10.3 后端新增命令构造函数

```python
def build_shh1_command(remote_command: str):
    return [
        SSH_EXE,
        "-n",
        "-o", "BatchMode=yes",
        "-o", "ConnectTimeout=8",
        "-o", "StrictHostKeyChecking=accept-new",
        "-i", SHH1_KEY_PATH,
        "-p", SHH1_PORT,
        f"{SHH1_USER}@{SHH1_HOST}",
        remote_command,
    ]
```

后续抽象 Runner 时，这里应该迁移到 `SshRunner`。

### 10.4 后端新增实时任务启动接口

新增：

```text
POST /v1/runs/shh1/demo
```

返回：

```json
{
  "message": "shh1 remote demo run started.",
  "data": {
    "run_id": "run_xxx",
    "status": "created"
  }
}
```

远程 demo 命令：

```bash
bash -lc "echo 'SimFEA remote terminal demo'; echo hostname=$(hostname); echo user=$(whoami); for i in 1 2 3 4 5; do echo remote_step=$i; sleep 1; done; echo done"
```

Python 字符串中 `$i` 必须写成：

```python
"for i in 1 2 3 4 5; do echo remote_step=\\$i; sleep 1; done; "
```

否则 `$i` 会被外层 shell 提前展开为空。

### 10.5 后端新增 SSE 事件流接口

新增：

```text
GET /v1/runs/{run_id}/events
```

使用：

```python
from sse_starlette.sse import EventSourceResponse
```

事件流数据格式：

```json

  "run_id": "run_xxx",
  "type": "stdout",
  "line": "remote_step=1"
}
```

完成事件：

```json
{
  "run_id": "run_xxx",
  "type": "finished",
  "status": "finished",
  "exit_code": 0,
  "line": "远程任务结束，退出码 0。"
}
```

### 11.1 修改文件

### 11.2 新增状态

### 11.3 新增 EventSource

新增：

```ts
let remoteEventSource: EventSource | null = null;
```

### 11.4 新增前端方法

新增：

```ts
const startRemoteDemoRunAction = async () => { ... }
```

流程：

1. 关闭旧 `EventSource`。
2. 调用：

   ```text
   POST /v1/runs/shh1/demo
   ```

3. 获取 `run_id`。
4. 创建：

   ```ts
   new EventSource(`http://${DOMAIN}:${PORT}/v1/runs/${runId}/events`)
   ```

5. 每收到一条事件：
   - 将 `payload.line` 追加到远程输出框。
   - 同时追加到全局日志窗口。
6. 收到 `finished`：
   - 设置 `running=false`。
   - 根据 `exit_code` 更新状态。
   - 关闭 EventSource。

## 16. 下一步开发建议

### 16.1 第一优先级：抽 Runner

3. 通过 `scp` 或 `sftp` 上传到远程：

4. 远程执行：

   ```bash
   bash run.sh
   ```

5. 实时回传 stdout/stderr。
6. 远程生成 `result.txt`。
7. 下载 `result.txt` 到本地：

   ```text
   .simfea/runs/<run_id>/artifacts/result.txt
   ```
