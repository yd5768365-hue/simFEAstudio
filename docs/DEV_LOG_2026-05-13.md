## 结构化引导笔记系统

### 设计问题

原有的三层结构（日志流 → AI 报告 → 用户笔记）顺序是错误的——用户应该先写笔记，AI 再生成报告，而不是反过来。

### 新三层顺序

```
第一层：日志流式回传（实时 SSE）
    ↓
第二层：结构化引导笔记（用户按问题填写）
    ↓
第三层：AI 学习报告（综合日志 + 用户笔记生成）
```

### 后端实现（`learning.py`）

**引导问题定义**：

```python

    "purpose": "这次运行的目的是什么？（验证模型？探索参数？复现结果？）",
    "expectation": "结果和你的预期一致吗？如果不一致，可能的原因是什么？",
    "confusion": "有什么没弄明白的地方？",

# 根据状态追加：
# finished + calculix → "结果是否符合理论值或经验预期？"
# failed → "你判断失败的原因是什么？"
```

## asyncio 子进程死锁修复

### 问题

Windows 上 `asyncio.create_subprocess_shell` 执行 `ccx.bat` 时挂起——ccx.bat 启动孙进程 `ccx.exe`，孙进程继承管道句柄，导致 `proc.communicate()` 永远等待管道关闭。

### 修复

用 `subprocess.run` 在线程池中执行，完全避开事件循环管道问题：

```python
async def _run_local_command(cmd: str, cwd: Path):
    loop = asyncio.get_running_loop()
    return await loop.run_in_executor(None, _run_local_sync, cmd, cwd)

def _run_local_sync(cmd: str, cwd: Path):
    proc = subprocess.run(
        cmd, cwd=str(cwd), shell=True,
        capture_output=True, timeout=120,
    )
    return proc.returncode, proc.stdout, proc.stderr
```

### TypedDict 修复

`T_Note` TypedDict 缺少 `answers` 字段声明，FastAPI 静默丢弃请求体中的 `answers` key。添加 `answers: dict` 到 TypedDict 解决。

## 学习报告核心能力补齐（下午）

### 目标

让学习报告从"模板填空"变成真正有分析价值的产物。三个能力：自动结果分析、数据感知问题、跨运行关联。

### 结果分析引擎（`analytics.py` 新增）

**功能**：
- 解析 CalculiX `.inp` 文件提取结构参数（梁长、截面尺寸、弹性模量、载荷、单元类型）
- 对 B31/B32/B33 梁单元自动计算 Euler-Bernoulli 悬臂梁解析解
- δ = PL³/(3EI)，σ_max = My/I
- 与仿真结果对比，计算误差百分比
- 根据误差大小生成不同级别的观察提示

**关键设计决策**：
- 仅对识别的单元类型提供分析，不编造对比
- B31 的应力是轴向平均值而非弯曲应力分布，误差可能较大——观察中如实提示
- 截面惯性矩按 RECT 截面 a³b/12 计算（a = local y, b = local z）

**`analyze_run(run_dir) → dict`**：返回分析结果和观察列表。
**`render_analysis_section(analysis) → str`**：渲染为 markdown 章节（对比表 + 理论假设 + 观察）。
